# 可选的随 App 启动 Wine 预热

- 在“设置 → 通用”加入默认关闭的“随 Arclume 启动并预热 Wine”；标准模式创建 Steam 容器前、剑网 3 初始化运行时页也展示相同选项。
- 仅预热当前模式已经初始化、无符号链接且由 Arclume 管理的 Steam/Games 容器，Runtime 不就绪时等待，不下载、不建新容器或迁移数据。
- GUI 子系统轻量助手保留一个 Wine 客户端，通过父进程管道维持生命周期；退出 App／异常退出关闭管道后释放，不使用永久 `wineserver -p`、全局进程名结束或 `wineserver -k`。
- 关闭选项只释放本次助手。用户手动停止 Wine 后当次暂停，不通过定时器复活。启动未就绪设 30 秒上限；不改变 D3DMetal 模块、窗口或游戏参数。
- 预热使用默认 MSync；若游戏显式关闭 MSync，先释放保温并等待空闲 server 正常退出，最多 8 秒；仍有后台进程时提示用户处理，不强制杀应用。
- 预热可能减少 Wine 公共初始化等待，不保证所有游戏提速，会额外占用内存；不提前加载游戏资源或替代客户端更新。未量化各应用启动提速。
- 回滚：关闭选项或退出 App，停止保温；用户游戏、注册表与登录数据不做重置。Wine 正常启动本身仍会维护其运行状态与注册表。
- 无 Runtime、ABI 或发布版本更改。

## 验证

- 无签名 Debug preflight 通过；`ArclumeCore` 定向 17 项测试通过，覆盖默认关闭、测试环境禁用、助手哈希、管道关闭后的正常退出和不影响另一进程，并回归 YY 与启动规则。
- 正式 Wine 真机助手两轮均 READY，关闭管道后返回 0；同会话第二客户端退出不影响第一个客户端。助手级对照首次 7.210 秒、保持会话后第二次 0.123 秒，不作为真实游戏提速倍数。
- 原生界面确认“设置 → 通用”开关可见、说明无裁切且默认未勾选；没有替用户启用偏好。未进行 UI XCTest、真实游戏冷启动基准、首启新容器或 App 崩溃场景的端到端测试。
- 使用现有 `script/build_and_run.sh verify` 构建并启动开发版，未覆盖 `/Applications` 中的发布版。
