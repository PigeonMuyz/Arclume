# 结束 Arclume Wine 的按钮内进度与退出确认

- 普通模式、剑三模式使用内置 Runtime 时，工具栏结束按钮原位显示小型进度指示器，禁止重复点击，不增加页面遮罩或进度窗口。
- 内置 Runtime 不再走按 `.exe` / `wine` 名称匹配可见 App 的关闭逻辑。通过内核进程列表、当前用户和 Arclume Runtime 目录边界识别进程，包括无窗口 wineserver；发信号前核对 PID、启动时间和实际可执行文件路径。
- 先发送 TERM，2 秒后升级到 KILL，并持续重新扫描新出现的进程；连续 600ms 未发现目标后才报告完成并清除运行状态。15 秒超时或检查失败明确报错，不假装已经退出。
- 取消尚未完成的内置 Steam 打开/安装任务；以启动代次和互斥检查阻止正在准备的内置游戏在停止后重新拉起。停止期间不接受游戏启动操作。
- CrossOver 仍保留其原有停止入口和行为；本次不扩大到用户独立的 CrossOver 或其他 Wine 安装。
- 普通模式内置游戏结束后的自动清理也复用限定范围的停止流程，避免其退出回调重新进入旧的全局关闭逻辑。

## 验证与影响

- 隔离原生进程 fixture（不运行 XCTest）：无窗口进程识别、忽略 TERM 后强制结束、保留另一个目录中的同名 Wine、新进程与短暂无目标复查、超时报错、旧启动代次失效。
- Debug build 与 pr_preflight；未在用户真实 Steam/剑三会话中执行强制退出，按钮实际交互仍需手工验证。
- 不改容器、游戏文件、Runtime 归档或版本，不提交或发布。强制停止本身可能丢失目标 Windows 程序未保存的数据；仅在用户点击结束按钮时执行。
