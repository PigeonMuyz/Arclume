# ALBottles 程序内迁移

新版以 `~/Library/Application Support/Arclume/ALBottles` 为唯一内置 Wine 容器。YY 也合并进入此容器。启动界面的网格/启动器样式只控制展示，不再选择另一套 Wine 数据。

## 升级流程

1. 退出所有 Windows 程序与其他 Arclume 实例，打开新版。迁移门禁先于游戏库及预热服务运行。
2. 点击“检查迁移条件”。只读取 Arclume 的 `WindowsGameWinePrefixes`、`OnlineGameWinePrefixes`、`CXPBottles` 直接子容器。不移动第三方 CrossOver 和外部 Steam 库。
3. 引导只展示检查结果与所需空间，不向普通用户枚举技术差异。优先使用现有 Steam 容器作为基础；否则按路径排序。应用文件/应用注册表/有效盘符冲突、大小写碰撞、符号链接祖先冲突仍会安全拦截，以简短错误和可导出的报告交付诊断。
4. 确认迁移后，公共 Windows 系统文件、系统注册表自动保留基础容器版本；已卸载安装盘的旧设备映射不导入。处理明细留在报告中。不同容器的公共依赖不能保证同时兼容，必要时要修复应用依赖。
5. 确认迁移后复制、逐文件 SHA-256/链接校验、合并注册表、复核源文件未变化、再次检查无 Wine 进程，随后记录事务并切换。磁盘需要至少一份完整副本加 512 MB 余量。
6. 原容器暂移至 `ContainerMigrationRecovery/<事务 UUID>/original-N`，旧路径改为指向 ALBottles 的兼容链接，偏好中的路径同步更新。清理前重新生成容器内 Steam 库的安全书签，外部库书签保留。
7. 切换校验成功后，先记录 `cleaning` 状态，再自动删除本事务的 `original-N` 与偏好快照，最后记录 `finalized`。只保留很小的事务记录和处理报告，不长期保留重复容器。完成页仅显示“升级完成”和进入按钮，不再提供完成后的回退入口。macOS 26 及以上使用原生 Liquid Glass 按钮，旧系统回退到 bordered 样式。

## 失败、异常退出与恢复

- `ALBottles-migration.json` 是应用读取的事务记录；恢复目录也保留记录、偏好快照及合并报告。
- 复制/校验阶段失败不更改原容器。切换阶段每一步可由原容器是否已移走来恢复；下次启动禁止载入未完成的数据。
- 在尚未提交清理的失败迁移页点击“恢复旧容器”，会恢复原路径、偏好，同时保留未启用的合并副本。失败时不删除原容器或新存档。
- 清理开始后不可回退（副本可能已经部分删除）；中断后仅重试剩余清理。仅校验本事务 UUID、ALBottles 标记及旧路径链接通过后操作已知目标，不递归清理整个恢复目录，不触碰其他事务。
- 兼容此前 `complete` 记录：下次启动先更新书签、执行清理，再允许进入游戏库。旧构建不理解新增阶段，完成升级后不可直接降级到旧构建。
- 不要手工删除/编辑事务记录、恢复目录或旧路径链接。遇到目标被替换、记录损坏、恢复副本缺失会停止，不猜测目录归属。
- 成功升级后旧副本已删除，无法用它恢复；ALBottles 中的应用和存档保留。不要使用旧版打开兼容路径。需要降级时先退出所有 Wine，保留完整 ALBottles 和新偏好，由维护者核对并回迁数据；不提供自动回退。
- 此机制不是防止其他程序恶意并发改写的安全沙箱；迁移期间不要从外部工具启动/修改 Wine 容器。

## 手工验证

- 先在隔离 fixture 测试空安装、单/多容器、文件与注册表冲突、符号链接、复制后源变化、切换各阶段中断、恢复和重复检查。
- 本机首次迁移由用户确认。迁移后分别检查 Steam/多库发现、剑网 3、终末地、YY 登录/频道/音频与长期运行；检查路径型启动参数、绿色版更新与卸载关联数据。
- 无签名 Debug build 与核心测试不代表已验证真实游戏或 YY 长时间运行。
